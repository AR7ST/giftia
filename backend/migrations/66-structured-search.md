# #66 構造化列を参照する検索への切替案
前提は #65 の3列追加と根拠のある値の登録。追加の DDL は不要。NULL の件数を監査し、従来の説明文から一致した商品と構造化列との不一致を管理者が分類する。

通常検索で個包装が指定された場合は、件数と明細の両方で `is_individually_wrapped = %s`（値は1）を使う。1のみ対象とし、0とNULLは対象外。現行の文字列検索が否定文を拾った場合は不具合修正として差分を記録する。理由の不明な欠落が残る間は切替を保留する。

送別検索の明細に個包装と保存方法を追加し、個包装の印は1、常温の印は管理者が確定した保存方法の値で表示する。包装可否は gift_wrap を維持する。香り・甘さは #65 に対応列がないため、既存の否定判定を維持する。賞味期限から表示を自動生成しない。

架空データで個包装1・0・NULL、否定文、常温・冷蔵・不明、ギフト包装のみ、香り・甘さを比較する。通常検索の件数と明細、送別の印と順序を照合する。切り戻しは検索コードを旧版へ戻す。#65 の列や登録値は保持する。
