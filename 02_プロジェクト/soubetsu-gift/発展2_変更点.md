# 要件定義書とGiftiaの変更点（クラス5・東京 Drinking Party）

発展2「要件定義をもとに Giftia を更新」／2026年11月9日

## 1. まとめ

要件定義書（提出用・11/7版）の FR-02「ない情報は『不明』と示す」と 5.2「評価なしを0点にしない」に、Giftiaがそろっていなかった。

評価がない商品が「評価0（0件）」と表示され、0点の商品に見えていた。

Giftiaを直し、「評価 不明（0件）」と表示するようにした。あわせて要件定義書に、実装の内容を記録した。

## 2. Giftiaの変更（As-Is / To-Be）

| 項目 | 変更前（As-Is） | 変更後（To-Be） |
|---|---|---|
| 評価がない商品のカード | 評価0（0件） | 評価 不明（0件） |
| 評価がある商品のカード | 評価4.4（387件）など | 変わらない |
| APIが返す評価（評価なしのとき） | 0 | null（なし） |
| 並び順・件数・検索条件 | 販売数の多い順・20件 | 変わらない |

変えたファイル（3ファイル・各1行）

| ファイル | 行 | 変更前 | 変更後 |
|---|---|---|---|
| backend/main.py | 87 | 評価がないとき 0 を返す | null を返す |
| giftia-frontend/lib/api.ts | 13 | rating: number | rating: number \| null |
| giftia-frontend/app/ResultCard.tsx | 10 | 評価{gift.rating} | 評価{gift.rating ?? " 不明"} |

画面とAPIのつなぎ目（評価の形）を変えるため、3つを同じPRでまとめて変えた。

PR #12（AR7ST/giftia）。班のメンバーがレビューしてmerge。

## 3. 要件定義書の変更

| 場所 | 変更前 | 変更後 |

| 5.2 の注記 | 現在の検索APIは、在庫ありの商品を販売数の多い順で返している（評価なしの扱いは書いていない） | 「評価がない商品は、APIがnullを返し、画面は『評価 不明（0件）』と表示する。評価がある商品の表示と並び順は変えていない」を追記 |
